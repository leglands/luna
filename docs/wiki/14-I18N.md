# LUNA i18n — Shipped Locales, Validation, and Backlog

> This repository still contains documentation translations and Android locale scaffolds, but release packaging is now intentionally limited to the locales that are complete and truthful.
>
> **Current production-safe state:**
> - **iOS app shipped locales:** `en`, `fr`
> - **Android app shipped locales:** `en`
> - **Docs translations:** 41 translated `README_*.md` files plus the main README
> - **Reviewed store metadata uploaded by Fastlane:** iOS `en-US`, `fr-FR` · Android `en-US`

---

## Audit snapshot

| Surface | Exact repo count | Truthful support status |
|---------|------------------|-------------------------|
| iOS string catalog | 2 locales after remediation (`en`, `fr`) | Both are complete and shipped |
| Android string resource dirs | 40 locale-specific dirs + default `values/` | Only default English is shipped; other dirs remain backlog scaffolds |
| Docs/i18n READMEs | 41 translated files | Docs only, not app-support evidence |
| iOS store metadata dirs | 42 locale folders | Fastlane uploads only `en-US` and `fr-FR` |
| Android store metadata dirs | 40 locale folders | Fastlane uploads only `en-US` |

### What the audit found before narrowing shipping

Before this remediation, the repo advertised far more locales than it could truthfully ship:

- the iOS string catalog contained **48 locale codes**, but only `en` and `fr` were complete
- Android contained **40 locale-specific resource directories**, but only default English had full key coverage
- the exact **cross-platform intersection of fully complete app locales was 1 locale: English**

That means the product must not claim “40 locales” or “40+ locales” today.

## Runtime behavior

### Locale selection

- the app follows the **system locale**
- only locales declared as shipped are considered production-ready
- non-shipped locale files in the repo must not be used as marketing evidence for locale support

### RTL

RTL engineering support still exists in the codebase:

- iOS uses directional layout primitives (`leading` / `trailing`)
- Android keeps `android:supportsRtl="true"` and directional XML attributes
- RTL locale packaging is deferred until translations are complete screen-by-screen

RTL is therefore an engineering capability, **not a shipped localization claim today**.

## Store metadata policy

Store listing localization is tracked separately from in-app locale shipping:

- App Store metadata may be translated for more storefronts than the app ships
- Google Play metadata currently uploads only the English reviewed listing
- misleading “40+ languages / full i18n” wording has been removed from the reviewed upload set
- legacy metadata folders remain in-repo as untranslated backlog and must not be re-enabled without review

---
