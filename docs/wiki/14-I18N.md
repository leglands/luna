## Platform Implementation

### iOS — Localizable.xcstrings

| Aspect | Detail |
|--------|--------|
| **Format** | `Localizable.xcstrings` (Xcode 15+ JSON-based string catalog) |
| **Location** | `ios-app/LunaApp/Resources/Localizable.xcstrings` |
| **Keys** | 100+ string keys |
| **Source language** | French (`fr`) |
| **Usage** | `String(localized: "key")` in SwiftUI |
| **Plurals** | Handled by `.xcstrings` plural rules (`.stringsdict` equivalent) |

### Android — strings.xml

| Aspect | Detail |
|--------|--------|
| **Format** | XML string resources |
| **Location** | `android-app/app/src/main/res/values-XX/strings.xml` (per locale) |
| **Default** | `res/values/strings.xml` (French) |
| **Keys** | Mirrors iOS key set |
| **Usage** | `getString(R.string.key)` or `@string/key` in XML layouts |
| **Plurals** | `<plurals>` elements with `quantity` variants |

## RTL Support

### Layout

| Platform | Mechanism | Detail |
|----------|-----------|--------|
| iOS | SwiftUI auto-flipping | `leading`/`trailing` instead of `left`/`right`. `Environment(\.layoutDirection)` |
| Android | `android:supportsRtl="true"` | `start`/`end` instead of `left`/`right` in XML layouts. Mirrored drawables via `autoMirrored="true"` |

### Testing RTL

```bash
# iOS Simulator — launch in Arabic
xcrun simctl launch 7A806776-2927-46EF-98F6-4D852C5AC671 \
  com.macaron.luna -AppleLanguages "(ar)" -AppleLocale "ar_SA"

# iOS Simulator — launch in Hebrew
xcrun simctl launch 7A806776-2927-46EF-98F6-4D852C5AC671 \
  com.macaron.luna -AppleLanguages "(he)" -AppleLocale "he_IL"

# Android Emulator — force RTL
adb -s emulator-5554 shell settings put global force_rtl 1
adb -s emulator-5554 shell am force-stop com.macaron.luna

# Android Emulator — specific locale
adb -s emulator-5554 shell am start -n com.macaron.luna/.ui.MainActivity \
  --es "language" "ar"
```

## Date & Number Formatting

### Dates

| Platform | API | Behavior |
|----------|-----|----------|
| iOS | `Date.FormatStyle` / `DateFormatter` | Automatically locale-aware. Calendar system adapts (Gregorian, Hijri, etc.) |
| Android | `DateTimeFormatter` / `SimpleDateFormat` | Locale from `Locale.getDefault()`. System calendar respected |

### Numbers

| Platform | API | Example (`fr`) | Example (`en`) |
|----------|-----|----------------|----------------|
| iOS | `NumberFormatter` | `36,5` | `36.5` |
| Android | `DecimalFormat` | `36,5` | `36.5` |

### Input Normalization (Postel's Law)

BBT and weight text fields accept both `,` and `.` as decimal separators. Input is normalized to `.` before parsing:

```
User types: "36,5" → stored as: 36.5
User types: "36.5" → stored as: 36.5
```

## Translation Workflow

```
1. Developer adds key in French (source) to:
   - iOS: Localizable.xcstrings
   - Android: res/values/strings.xml

2. Translation to 39 target languages (batch)

3. Verify:
   - String length (German ~30% longer than English)
   - RTL layout (ar, he)
   - CJK line breaking (ja, ko, zh)
   - Plural rules (Slavic languages have complex plural forms)

4. Build & test on simulator:
   - xcrun simctl launch with -AppleLanguages
   - adb locale change
```

## Key Translation Considerations

| Concern | Detail |
|---------|--------|
| **String expansion** | German strings ~30% longer than English. UI tested with `de` to catch overflow |
| **Plural forms** | Slavic languages (pl, cs, sk, hr, sl, sr, uk, ru, bg, lt, lv) have 3-4 plural forms. Arabic has 6 |
| **Gender** | Avoided gendered strings where possible. French source uses inclusive forms |
| **CJK** | No spaces between words — line breaks handled by system text layout engine |
| **Script mixing** | Numbers always use ASCII digits in UI (not Arabic-Indic). Date formatting deferred to system |
| **Symptom names** | 43 symptoms translated per language — medical terms verified for accuracy |
